# STP1: Boundary-aware calibrated gating for sensitive agent actions

CS 48013/58013 Human-Centered AI, Short-Term Project 1 (Project 12: user-defined boundaries for AI agents and sensitive actions).

The code decides whether a tool call proposed by an AI agent should be **executed**, **confirmed with the user**, or **blocked**. It compares two baselines, two human-centred designs and their ablations on a seeded, fully synthetic scenario suite.

| Policy | What it does |
|---|---|
| `B0_broad` | Executes every proposal (one-time broad permission). |
| `B1_always_ask` | Asks before every proposal. |
| `A_rules` | **Design A.** Applies the user's stated allow/ask/deny rules directly. Unruled pairs fall back to a static tier: irreversible or external actions → ask. |
| `B_full` | **Design B.** Gradient-boosted P(approve) from action features plus the user's boundaries, with isotonic calibration. Deny rules are hard constraints. Uncertainty band (τ_lo, τ_hi) → ask. |
| `A_no_ask_tier`, `B_no_boundaries`, `B_no_ask_band`, `B_soft_deny` | Mechanism-check ablations: each removes one component. |

## Environment

- Python 3.11.7 (tested on macOS 14, Apple M1)
- `pip install -r requirements.txt` (numpy 1.24.3, pandas 2.0.2, scipy 1.11.3, scikit-learn 1.3.2, matplotlib 3.8.1)
- No GPU, LLM, API key or external data needed.

## Run

```bash
python run_experiments.py --seeds 10 --out results   # ~3 min on an M1 laptop
python make_figures.py --res results --fig ../report/figures --tab ../report/tables
```

`results/` will then contain:

- `per_seed.csv`: every policy × seed × habituation level
- `summary.csv`: mean ± 95% t-CI across seeds
- `paired_ablation.csv`: paired differences (ablation − full design)
- `subgroups.csv`: by user archetype, reversibility, rule presence and mistake type
- `calibration.csv`: AUROC, Brier and ECE of the risk model, raw vs. isotonic
- `coverage.csv`: rule-coverage sweep (5 seeds)
- `data_stats.json`: test-set statistics and tuned thresholds per seed
- `cases_seed0.json`: representative successes and failures

## Data

Fully synthetic. The data is generated by `boundaries/sim.py`, with no personal data and no licence restrictions.

- 300 users per seed from 3 archetypes: conservative 30%, balanced 45%, delegator 25%.
- Each user receives 60 proposals.
- 8 tools, 5 data categories, 5 recipient classes, 3 scope levels.
- Ground truth: the user approves iff a latent score > 0. The score combines tool risk, data sensitivity, recipient, scope, a per-user × (tool, category) offset (σ = 0.6) and action noise (σ = 0.5).
- **Boundaries:** each user writes rules for 60% of the 40 (tool, category) pairs. Rules come from the user's typical score (allow > 1, deny < −1, else ask) and are flipped with probability 0.05.
- **Injected agent mistakes (15%):** off-task, wrong recipient, overbroad scope.
- **Split by user:** 60/20/20 train/val/test, i.e. 180/60/60 users per seed. Test users are unseen.
- **Seeds:** 0–9 for the main runs, 0–4 for the coverage sweep. The seed controls data generation, the split (`seed + 999`), model `random_state` and simulated confirmation responses. Threshold tuning uses a fixed RNG seed of 12345.

## Model and settings

- `HistGradientBoostingClassifier(max_iter=300, learning_rate=0.05, max_leaf_nodes=31)`
- `CalibratedClassifierCV(method="isotonic", cv="prefit")`, fitted on validation users.
- Thresholds: grid 0.02…0.98 (step 0.02), chosen on validation users to minimise expected cost.
- Simulated confirmation: the user answers correctly with probability `0.98 − k · ask_rate`. The default is k = 0.15, and the scripts also report k ∈ {0, 0.30}.

## Metrics (defined before running)

| Metric | Definition | Why |
|---|---|---|
| UER | P(executed \| user would not approve), including wrongly confirmed actions | Primary safety outcome |
| FBR | P(not executed \| user would approve) | Over-restriction |
| Ask rate | Share of proposals that trigger a confirmation | Interruption burden |
| Autonomy | P(executed without asking \| approve) | Delegation benefit |
| Mistake exec. | P(executed \| injected agent mistake) | Robustness to agent errors |
| Cost | Mean per proposal: 10 × unintended + 2 × false block + 1 × ask | One-number summary. Depends on the weights. |
| AUROC / Brier / ECE (10 bins) | Discrimination and calibration of P(approve) | Probability quality of the risk model |

Uncertainty is reported as mean ± 95% t-interval over seeds. Ablations use paired (same-seed) differences.

## Known limitations

- Synthetic ground truth from the same feature family the model sees. This favours learned models, so the results are not evidence of a benefit for real users.
- Users are assumed to state rules consistent with their preferences.
- The fatigue model is a single linear term.
- No real LLM agent is involved. Prompt injection is only approximated by the off-task mistake type.
- No online learning from confirmation answers.
- The cost weights are a value judgement.
- Not a security boundary. Do not use it with real accounts or actions.
